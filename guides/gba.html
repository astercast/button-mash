Game Boy Advance emulation guide

The easiest classic system to emulate: one excellent core, zero BIOS files, and games that run at full speed on practically anything with a screen. If you're starting your first emulation project, start here.

1. The core: mGBA, the accuracy king

The Player's gba core is mGBA — the core name is taken from the official EmulatorJS core list, where mGBA is the single backend for Game Boy Advance. mGBA is one of the most accurate GBA emulators ever written, and because the GBA is modest hardware, that accuracy comes almost free: near-perfect compatibility with a huge game library.

You don't need to pick anything — the Player detects .gba files and boots mGBA automatically. The manual system dropdown is only there if detection fails.

2. BIOS notes (the short version: none)

Real GBA games sometimes call into the console's built-in firmware (the BIOS) for math routines. mGBA reimplements those calls from scratch (clean-room high-level emulation), so the core boots with no BIOS file at all. Nothing to dump, nothing to attach, nothing to download. This is the friendliest BIOS story in emulation — GBA, Game Boy, and SNES all share it.

3. Settings that matter

Open the engine's in-game menu (the ⚙ icon) while a GBA game is running. Most defaults are right; the ones worth knowing:

  • Color correction: GBA games were drawn for the original's dim, unlit screen, so they look washed out on bright displays. mGBA's color-correction option restores the look the artists intended. Check the core's Settings/Options for it.
  • Fast-forward: the handiest feature in retro gaming — hold it to blast through slow intros or grindy stretches.
  • Save states: instant snapshots anywhere (see Saves & cheats). In-game battery saves also work, stored by the engine.
  • Keep in Browser: under Settings → Save States, switch the engine to Keep in Browser if you want the Player's Save tool to export/import your states as files (Player 2.0 feature).

4. Performance: it just runs

GBA is the lightest system in the Player. Any laptop, desktop, tablet, or phone from the last decade runs it at full speed in a browser. If you ever see stutter, the usual suspects are: too many tabs open, a low-power mode throttling the browser, or the game's own slowdown (the real hardware slowed down too — that's authentic).

5. Saves & cheats in the Player

  • Save states — made in the engine's in-game menu. With Keep in Browser on, the Player 2.0 Save tool (below the console on player.html) can export them as files, import them on another device, or delete them.
  • In-game saves — battery and flash saves work normally; the engine persists them automatically.
  • Cheats — the Player 2.0 Cheats tool accepts GameShark and Action Replay v3 codes, stored per game and injected before boot. Toggle them in the engine's cheat manager. Per-core code-format behavior isn't verified, so if a code glitches, try the other format or disable it.
  • Keyboard remap — the Player 2.0 Controls tool remaps Player 1's keyboard and gamepad bindings; changes apply on next boot.

8. Prefer a desktop app? mGBA

The same mGBA core runs as a standalone desktop app (mgba.io) — same accuracy, plus debugging tools and link-cable-over-network. The browser Player wins on convenience; the desktop app wins on power features.
