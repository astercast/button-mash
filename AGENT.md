# PortPlay — agent guide

PortPlay is a static, client-side game converter and player. There is no
game catalog API anymore: the library API (`data/v1/games.json`,
`collections.json`, and friends) was retired with the library itself in the
2026-10-15 rebuild. What remains for machines:

## `GET data/v1/coverage.json`

The converter's coverage, generated by `scripts/build.py` from the
converter engines' own code (never hand-written, so it cannot drift):

- `convert` — systems that convert to a portable single-file HTML game
  (name, formats, core, max size).
- `play` — systems that play in the browser (name, formats), including
  disc-image routes identified by content.
- `guide` — systems PortPlay declines, each with its tone
  (`guide-only` / `not-yet`) and the guide page anchor for its path.
- `dos` — the DOS room's intake formats.

## `GET api/health`

Envelope response (`{ ok, data, meta }`): service `portplay`, status,
the function list (`["health"]`), and the state of the static coverage
file. Never returns 5xx; a problem reports `status: "degraded"` in a 200.

## The rules agents must keep

- PortPlay hosts no games and links to no game downloads, BIOS, or
  firmware. Do not add any.
- Coverage claims come from the code: extend `converter-core.js` /
  `converter4-core.js` and let `build.py` regenerate the JSON. Never
  hand-edit `data/v1/coverage.json`.
- Every decline needs a guide anchor in `guide.html`; the build fails
  without one.
- Presented copy carries no em dashes.
