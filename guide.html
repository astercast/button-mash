The converter's other half

The games a browser cannot convert.

Some games cannot become browser games today, and PortPlay will not pretend otherwise. For every system the converter has to decline, here is the working path: native emulation, decompilation, recompilation, or a source port, using your own copy throughout. Legal lane, always: dump your own media, from hardware you own, with your own tools. Never download game files, BIOS, or firmware; every project named here ships without the game, and you feed it yours.

Four paths, plainly told

A graceful, specific no, with a working path attached, is worth more than a vague maybe. Every path below starts from the same place: a game you own, dumped by you. Emulators, decompilers, and recompilers are legal tools. The game files, and the BIOS and firmware inside your consoles, are yours to extract and nobody else's to give you.

Path A: native emulation

The game runs inside an emulator program on your computer. Not browser play, but for the big systems it is excellent today: PCSX2 for PlayStation 2, Dolphin for GameCube and Wii, RPCS3 for PlayStation 3, xemu for the original Xbox, Xenia for Xbox 360. Each keeps a compatibility list; check your game before you invest an evening, because per-game support varies more than any project's marketing admits.

Path B: matching decompilation

A community rebuilds the game's source code by hand, function by function, until compiling their code produces bytes identical to the original. A finished decompilation is portable source, but two honest facts apply: the repos contain no game assets, so building one requires your original disc or cartridge, which the build verifies; and a finished decomp is not a finished port, somebody still writes the renderer, inputs, and platform code. Progress lives at decomp.dev.

Path C: static recompilation

A tool translates the game's machine code into C automatically, ahead of time, and a small runtime stands in for the console. It is newer and far faster than hand decompilation, and it produced the most impressive ports of the last few years: Zelda 64: Recompiled for Majora's Mask in 2024, and Unleashed Recompiled, a native PC port of the Xbox 360 Sonic Unleashed, in 2025. A recompiled game is ordinary C, so it can in principle be compiled to WebAssembly; today the ports target native first.

Path D: source ports and engine recreations

The oldest path. Some engines were open-sourced by their makers, id Software's Doom and Quake are the famous ones, and communities have rebuilt hundreds of others. The engine is new; the levels, art, and music still come from your copy. ScummVM is the friendliest example: point it at a folder of your adventure game's files and it simply runs them. Many of these ports have web builds, one title at a time, which is where most real PC-games-in-a-browser actually come from.

Find your system

PlayStation 2 Guide only

No browser engine plays the PS2 library today. The one browser build that exists drops whole classes of games, and the emulator that plays the library properly, PCSX2, has no web version.

Install PCSX2 on your computer, dump the BIOS from your own PlayStation 2, load this disc image, and play. Your saves live in PCSX2 memory cards you control.

GameCube Guide only

Dolphin, the GameCube and Wii emulator, has no browser build; the one WebAssembly prototype is a single-game research demo. On a computer, Dolphin plays GameCube games beautifully, many better than the original hardware did.

Your file is already in a format Dolphin reads (.iso, .gcm, .rvz, and .wbfs all work). Any gamepad works; a GameCube controller adapter works too.

Wii Guide only

Beyond the missing browser engine, Wii games expect a Wii Remote: pointer aim and motion have no honest equivalent in a browser tab. Dolphin on a computer handles both, emulated with a mouse and pad, or with a real Wii Remote over Bluetooth.

Load your disc image (.iso, .rvz, .wbfs) and map the remote, or pair a real one.

PlayStation 3 Guide only

The PS3 chip is a PowerPC core welded to eight co-processors; RPCS3 asks for a strong desktop CPU and a modern graphics card even running natively. A browser tab is not close, and this site will not pretend otherwise.

Install RPCS3 on a desktop computer (a mid laptop will frustrate), install the PS3 system software from the update file for your own console, and check your game on the RPCS3 compatibility list first.

Xbox (original) Guide only

The Xbox emulator xemu is a full PC-class machine emulator with no browser build anywhere. It also needs two small files dumped from your own Xbox, which is exactly the kind of thing this guide exists to walk through.

Install xemu, dump the MCPX boot ROM and BIOS from your own Xbox, convert your disc dump to XISO format, and check the xemu compatibility list; about the popular half of the library plays well.

Xbox 360 Guide only

Xenia, the 360 emulator, is native-only and needs a modern CPU and graphics card. The interesting exception: a few 360 games have been statically recompiled into native PC ports, Sonic Unleashed among them, and those ports are the best way those games exist anywhere.

Install Xenia on a Windows computer with a Vulkan-capable graphics card and load your own dumped disc image or install folder. If your game has a Recompiled release, use that instead; Path C explains how to find out.

Nintendo Switch Guide only

This one is a matter of care, not just power, and the exception is deliberate, not an oversight. The Switch emulators were shut down under legal action in 2024, and pointing you at what replaced them would put you and this site at risk. This guide carries no Switch emulator walkthrough.

Your games play on the hardware you own. What PortPlay can honestly help with is preservation: back up your saves from your own console so a lost machine is not a lost library, and keep cartridges and receipts; a cared-for collection outlives every storefront.

Nintendo 3DS Guide only

A browser core for the 3DS exists now, and PortPlay still will not route your game to it. 3DS games are encrypted: a working copy needs keys and decryption from your own console, the files run to gigabytes, and browser performance is unproven. Pretending that is a drop-and-play conversion would break this site's one promise.

Install Azahar on your computer, decrypt the dump with keys from your own 3DS (an encrypted dump plays nowhere, including here), and load the decrypted copy. Your saves and your console's keys stay yours throughout.

Wii U Guide only

No browser engine plays Wii U games at all. Cemu, the native Wii U emulator, plays much of the library well on a computer, GamePad screen included.

Install Cemu, dump your game and its keys from your own Wii U with the console's own homebrew dumping tools, and load the dump (.wud, .wux, or an extracted folder). Map the GamePad to your controller, or put it on a second screen.

PlayStation Vita Guide only

No browser engine plays Vita games. Vita3K, the native Vita emulator, plays a growing share of the library and needs the Vita system files to do it well.

Install Vita3K, install the Vita firmware from the update file for your own console, then install your game package (.vpk) inside Vita3K. Check your game on the Vita3K compatibility list first; support is per game and younger than the other paths here.

PSP On the bench

PSP in the browser exists as an experimental core, and PortPlay does not ship experiments under a promise. The native emulator PPSSPP is excellent, runs on almost anything, and needs no BIOS; it carries its own replacement firmware.

Install PPSSPP on your computer or phone and load this file; it reads .iso, .cso, and .pbp dumps of your own UMDs and purchases.

Sega Saturn On the bench

Saturn emulation is real in browser cores, but it is the first system where "your game may run slowly" has to be said out loud, and it needs a BIOS dumped from your own Saturn.

Native path today: RetroArch with the Beetle Saturn core, or Yabause for lighter machines. CHD is the kindest format for Saturn discs if you convert your dumps on your computer.

Dreamcast On the bench

The Dreamcast emulator Flycast is strong natively, but its browser build is the unstable end of the spectrum, so it waits here rather than shipping wobbly. Flycast can even boot through a built-in replacement BIOS when you have no dump handy.

Install Flycast and load this file; it reads .gdi, .cdi, .cue, and .chd dumps of your own discs. A BIOS from your own Dreamcast improves compatibility but is optional.

More systems, plainly

A few more formats a collection can hold, and where each one honestly stands.

Arcade and Neo Geo cabinets

The browser engine family includes an arcade core (FBNeo), and the full Player offers it as a manual system: pick Arcade there, then drop your cabinet ROM set ZIP. The converter stage will not guess at a ZIP, because a cabinet set is many files whose identity a single drop cannot prove, and a wrong guess would boot the wrong game or none. Natively, FBNeo and MAME remain the reference path, with the ROM set version matched to the emulator version.

TurboGrafx-CD and PC Engine CD

These discs play on the same PC Engine core as the cartridges, but they need the System Card BIOS dumped from your own console. In the full Player, pick TurboGrafx-16 yourself and attach the System Card with the BIOS picker before dropping the disc set. A cue sheet dropped cold still defaults to PlayStation, because a cue sheet does not name its system; the manual pick is the honest route.

The other Commodores

The Commodore 128, VIC-20, PET, and Plus/4 all have working cores in the same VICE family as the 64, and all of them share the same program file forms. A .prg cannot name its machine, so the converter sends it to the Commodore 64, the machine most such files belong to. If yours is for a sibling machine, the VICE package runs all five natively, one emulator per machine.

Systems with no browser core in the engine family

Intellivision, Vectrex, Odyssey 2, Channel F, MSX, ZX Spectrum, Amstrad CPC, Atari ST, the Atari 8-bit computers, Apple II, PC-FX, Neo Geo CD, and Philips CD-i: no core for any of them ships in the engine this site loads, and most of their common file forms are ambiguous disc images or bare .bin files that another system also uses, so the converter will not pretend to recognise them either. Every one has a mature native emulator (Hatari for the ST, Altirra for the Atari 8-bits, AppleWin for the Apple II, openMSX for MSX, Mednafen for PC-FX are the usual starting points), and the dumping section below is step one for all of them. Amiga CD32 discs are the one partial exception: the Amiga route in the full Player can boot many of them with a CD32 Kickstart from your own console attached.

Start at the beginning: your own files

Whichever path your game takes, step one is the same: get your game off its disc or cartridge and onto your computer, legally.

  • Cartridges: a USB cartridge reader (the Retrode and GBxCart RW class of tools) reads the ROM and, just as important, the save file inside your cartridge. Insert your cart, read, verify the size looks sane, and keep the dump with the cartridge's name.
  • Discs: many consoles' discs read in an ordinary PC drive with the right software; the Redump project's guides are the reference pattern for clean, verifiable rips. Some systems need the console itself or a specific drive; when a decline card names a dumping step, that is the step that matters.
  • Console files and saves: BIOS, firmware, and saves come off your own console, by its own backup tools or a softmod; never by download. A save backed up is a library that survives dead hardware.
  • PC games: an installed folder from your own machine usually is the game; copy it whole, executables and data together, and it is ready for the DOS room or a source port.

A note on freshness: decompilation percentages and emulator statuses drift monthly. Figures in this guide carry their date (October 2026); the live trackers, decomp.dev for decompilation progress and each emulator's own compatibility list, are the authority. A stale figure here is a bug, not a cosmetic issue, and this page gets a regular pass.
