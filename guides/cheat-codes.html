Cheat codes, decoded

Every cheat code ever typed is the same small idea wearing different costumes: find where the game keeps a number, and change the number. This guide takes the idea apart — the Konami Code, the Game Genie, the lawsuit that settled whether any of it was legal, and how to hunt down codes of your own.

  • Covers: Game Genie · GameShark · Action Replay · RetroArch · this site's Player
  • ⏱ ~12 min
  • Beginner
Legal lane: cheat codes are numbers, not downloads — typing one into a game you own is yours to do (a US federal appeals court said so in 1992, see section 4). Nothing here links to ROMs, BIOS files, or trainer programs. Cheats are for your own single-player games; keep them out of other people's multiplayer matches.

01What a cheat code actually is

Strip away the branding and a cheat code is two things: an address (where in memory the game stores something — your lives, your health, your ammo) and a value (what to put there, or what to force it to stay at). "Infinite lives" is not a spell. It is one byte, somewhere in RAM, that the game decrements every time you die — and a code that keeps writing the same number back into it.

That gives cheat codes two families, and the split explains almost everything else in this guide:

RAM codes
Watch a spot in the console's working memory and hold it at a value, or poke a new value in. GameShark and Action Replay codes work this way, and so do most emulator cheat engines. Turn the code off and the game goes back to counting normally.
ROM patches
Change what the game's own program says as the console reads it — swap one instruction or constant for another, mid-stream. The Game Genie works this way. The cartridge itself is never written to; the patch exists only while the machine is on.

One practical consequence: a code is written for one version of one game. The address that holds lives in the US release may hold something else entirely in the European one, which is why codes copied from a forum sometimes do nothing — or freeze the game. Region and revision are part of the code, even when nobody writes them down.

02Built-in codes: the Konami Code

The oldest cheats needed no hardware at all, because the developers put them there. The famous one — ↑ ↑ ↓ ↓ ← → ← → B A — was written by Konami programmer Kazuhisa Hashimoto while he was porting the arcade shooter Gradius to the NES in 1986. Hashimoto found the game too hard to play through while testing it, so he gave himself a sequence that handed over the full power-up set. He picked a sequence he could remember and that nobody would type by accident — and then the code shipped, still in the game, because removing it never happened.

Players found it, word spread, and Konami kept the sequence in later games on purpose. It became legend in 1988, when the NES version of Contra — a game stingy enough to be famous for it — answered the code with 30 lives instead of the usual three. A generation of players can still type it from muscle memory, and the sequence has been turning up as an Easter egg in games and software ever since.

Built-in codes come in a few other shapes worth knowing:

  • Debug leftovers: level selects, sound tests, and invincibility toggles left in from development. Some were meant to ship; some are scaffolding nobody removed.
  • Passwords: not cheats exactly — a password screen encodes your progress, and a "password" that starts you at the last level with everything unlocked is the developer's own back door.
  • Name-entry codes: typing a specific name or initials triggers an effect. Same idea, friendlier costume.

03The Game Genie: a cartridge that lies

The Game Genie, developed by the British studio Codemasters and sold by Galoob in the US (Camerica in Canada), arrived for the NES in 1990. It was a pass-through cartridge: the game plugged into the Genie, the Genie plugged into the console, and every byte the console asked the cartridge for passed through the Genie first. When the console read an address the player had targeted, the Genie handed back a different byte than the one on the cartridge. The game never knew. The cartridge was never modified — pull the Genie out and the game is factory-stock again.

Those mysterious letter codes are just the address and value scrambled into an alphabet of sixteen letters so kids could copy them out of magazines without hex errors:

  • Six-letter codes decode to an address in the game's ROM plus a replacement byte. Every time the console reads that address, it gets the replacement. Unconditional.
  • Eight-letter codes add a compare byte: the replacement is only served when the byte actually on the cartridge matches the compare value. Later NES games swapped banks of ROM in and out of the same address window, so several different bytes could live at one address — the compare byte is how a code says "only patch it when the right bank is showing."

Versions followed for the SNES, Game Boy, Genesis, and Game Gear, but the trick stayed the same, and so did the limit: a ROM patch can only change what the program says, not what the console remembers. Freezing a RAM value like a countdown timer was the next generation's job.

04The court case that made it legal

Nintendo did not care for an unlicensed cartridge that rewired how its games played, and sued Galoob for copyright infringement, arguing the Game Genie created unauthorized derivative works of its games. US sales were halted while the case ran (Canada, outside the injunction, kept selling — magazine ads of the era thanked Canadian players for it).

The courts sided with Galoob. A federal district court ruled in 1991, and the Ninth Circuit Court of Appeals affirmed in 1992 in Lewis Galoob Toys, Inc. v. Nintendo of America, Inc.: the Genie created no permanent altered copy of any game — switch the console off and nothing remained — and a player's use of it at home was fair use, in the same spirit as skipping ahead in a book you own. Sega, for its part, went the other way entirely and gave the Genesis version its official seal of approval.

Why this still matters: the ruling is the legal ground every cheat device, emulator cheat engine, and this site's Cheats tool stands on. Modifying how a game plays on your own machine, for your own play is not infringement. It says nothing about distributing copies of games — that lane stays closed, which is why this site hosts none.

05GameShark & Action Replay: the RAM years

The disc era changed what a cheat device had to be. Games now loaded from CD into comparatively roomy RAM, and the interesting numbers — health, money, items — lived in memory, not on the disc. The British company Datel's Action Replay line went after RAM: find the address, hold the value. When InterAct brought Datel's devices to the US in 1996, it sold them under a new name — GameShark — which is why the two brands' codes are interchangeable for the PlayStation, Saturn, and Nintendo 64 era: same hardware family, different badge.

These codes look different from Genie letters because they are barely encoded at all: a string of hex that reads, more or less, as address, value. The Pro models went further and added code searching — snapshot memory, change something in the game, snapshot again, and keep the addresses that moved the right way. That search is the single most useful cheat skill there is, and section 7 walks through it, because modern emulators have it built in.

The brands faded as consoles moved online and started patching themselves, but the format never died. Open a cheat file for a modern emulator and you are looking at the GameShark's homework: lists of addresses, values, and plain-language names.

06Cheats in emulators & this site's Player

Emulators fold all of the above into the cheat engine of each core: codes are decoded to address-and-value pairs and applied as the virtual machine runs, which is why one engine can accept Game Genie, GameShark, and Action Replay formats side by side. Support is per-core, not universal — a code format the core doesn't speak simply won't take.

On this site, the Player's Cheats tool (on player.html) works like this:

  • Boot a game you supplied, then add codes under the Cheats card — a name and the code itself. Codes are stored per game, in your browser only.
  • At boot, your codes are handed to the engine's cheat manager (the documented EJS_cheats list). Toggle individual codes on and off from the cheat icon in the in-game menu.
  • Codes are injected before boot, so a code added mid-session takes effect on the next boot of that game.

Honest limits, the same ones the Player card itself states: code formats are applied by each core's own cheat engine, what works varies by system, and none of it is guaranteed. A code written for a different region or revision of the same game is the usual suspect when nothing happens — and a code that glitches the game should be switched off in the cheat manager, not fought with. The per-system guides carry the cheat notes for their machines: the NES guide covers Game Genie codes in the Player, and the PlayStation guide covers the GameShark's home turf.

07Find your own codes: the memory search

You do not need to wait for somebody to publish a code for the thing you want to change. If a game displays a number — lives, health, coins, a timer — that number lives at an address, and a memory search finds it by elimination. This is the same technique the GameShark Pro put on a cartridge menu, and RetroArch has shipped it built in since version 1.7.4 (Quick Menu → Cheats → Start or Continue Cheat Search):

  1. Start the search with a value on screen. Pick a bit size that fits the number: lives are small (8-bit is plenty), health bars and money can run bigger (16-bit).
  2. Change the number in the game. Lose a life, spend some coins, take a hit — then search again for values that went down (or up, or to an exact new number). Every pass throws away every address that didn't move the right way.
  3. Repeat. Thousands of candidates become dozens, then a handful. Run out of lives mid-search? Reload a save state — your count goes back up, so search for greater than before and keep going. (States and searches are natural partners; the save workflows guide covers keeping the states themselves safe.)
  4. Add the survivors to your cheat list and test them one at a time: set the value you want, and watch whether the game obeys. The address that holds is your code — name it, save the cheat file, and it loads with the game from then on.

Two traps, both classic. Some games store a number transformed — doubled, offset, or displayed one higher than stored (a lives counter that shows your spare lives, not your current one) — so an exact-value search comes up empty while a greater/less search still works. And some addresses are decoys: the display copy of a number, refreshed from the real one every frame. Freeze the display copy and the number looks locked while the game keeps counting underneath. Test before you celebrate.

08Cheat manners: where codes don't belong

  • Your game, your rules. In a single-player game, a cheat is a difficulty dial the developer didn't ship. Nobody's run is harmed by your 30 lives.
  • Other people's games are off-limits. In multiplayer and netplay, a memory cheat stops being a dial and becomes tampering with a shared session — and practically, most netplay desyncs the moment one side's memory disagrees with the other's. See the netplay guide for why both sides must run identical state.
  • Achievements keep their own house rules. Hardcore achievement modes lock cheats (and usually save states) out on purpose: the badge certifies an unassisted run. Play assisted all you like — just not under the hardcore flag.
  • Save before you experiment. A wrong address can corrupt a save or wedge a game mid-write. Keep one clean in-game save that no session with codes switched on ever touches.
  • One code at a time. When a game freezes, the last code added is the first suspect. Stack codes after each has proven itself alone.

The through-line, from Hashimoto's test code to the Galoob ruling to the search box in a modern emulator: cheating at your own games was never the shady part of this hobby. It is players poking at machines they own, learning how the numbers move — which is, not coincidentally, where a lot of programmers started.
