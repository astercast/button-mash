EmulatorJS self-hosting guide

Host the open-source EmulatorJS player on your own site and play ROMs you dumped yourself — setup, cores, BIOS, and the legal line.

  • ⏱ ~30 min
  • Intermediate
Legal lane: this guide covers tools and techniques only. Supply ROMs you dumped from games you own, plus homebrew and public-domain titles. No ROM download links, no piracy sites — ever.

What it is (and the legal line)

EmulatorJS is a free, open-source project that puts classic console emulation in a web page. It bundles libretro cores compiled to WebAssembly, so systems from the NES to the GBA run right in the browser with no plugins.

The software itself is completely legal — and it ships with zero games. You supply the game files, and this is the part that matters: only load ROMs you dumped from cartridges or discs you own, plus homebrew and public-domain titles. Downloading commercial ROMs you don't own is piracy, no matter how nicely the player is skinned.

What you need

  • A web host that serves static files (any static host works), or just your own computer for local play
  • ROM files you dumped yourself — see the rip-your-own-cartridges guide
  • For some systems, a BIOS file dumped from hardware you own (GBA and PlayStation cores need one)
  • About 30 minutes

1. Get the release

Grab the latest release ZIP from the project's GitHub releases page (github.com/EmulatorJS/EmulatorJS) and unzip it into your site folder. The ZIP contains the loader, the cores, and a data directory — no installer, no build step.

If you'd rather not self-host, the project's own demo page shows the same setup; the steps below work identically on any static host.

2. Add your own games

Create a folder (call it roms) and copy in only ROMs you dumped from games you own, plus homebrew or public-domain ROMs. One subfolder per system keeps cores straight — roms/gba/, roms/snes/, and so on.

Name files clearly. EmulatorJS doesn't care about fancy naming schemes; it cares that the file is a valid dump.

3. Embed the player

Drop this into an HTML page where you want the game to appear:

<div id="game"></div>
<script>
EJS_player = '#game';
EJS_core = 'gba'; // the core for your system
EJS_gameUrl = 'roms/gba/mygame.gba'; // a ROM you dumped yourself
EJS_pathtodata = 'data/'; // EmulatorJS data directory
</script>
<script src="data/loader.js"></script>

Swap EJS_core for the system you're playing (snes, nes, gb, gba, n64, nds, and more are supported). The full core list is in the project's documentation.

4. BIOS files (dump your own)

Some cores refuse to boot without a system BIOS. Dump the BIOS from hardware you own — the same dumpers in the rip-your-own guide usually handle this — and place it where the core's documentation says to look. Never download a BIOS file; like ROMs, they're copyrighted software.

5. Extras worth knowing

  • Gamepad support is built in; most USB and Bluetooth controllers just work
  • Save states live in the browser; export them if you switch devices
  • Netplay is available for some cores if you want online multiplayer
  • On mobile, add the page to your home screen for a near-native feel

The rule, one more time

EmulatorJS gives you the player, not the games. If a setup tutorial tells you to download a ROM pack, close the tab — that tutorial is pointing you at piracy. Your library should be: dumps of games you physically own, homebrew from its authors, and public-domain releases. That's the whole legal lane, and it's plenty.
