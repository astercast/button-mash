# GO_LIVE — PortPlay

> Working repo (`astercast/button-mash`) is never deployed. The live site
> is the snapshot repo `astercast/button-mash-live`, updated only on the
> user's explicit push order. This file describes the current (PortPlay)
> surface for the next snapshot.

## 1. What deploys

One Vercel project: **static frontend + 1 serverless function**. No crons,
no secrets, no environment variables. PortPlay's conversion and play run
entirely in the visitor's browser.

| method | path | file | purpose |
|---|---|---|---|
| GET | `/api/health` | `api/health.js` | status envelope; reports the static coverage file's state |

Static pages: `index.html` (the Stage), `player.html` (the Console),
`dos.html` (the DOS room), `guide.html`, `404.html`.
Static data: `data/v1/coverage.json` (generated by `scripts/build.py` from
the converter engines; the only runtime data file).

## 2. Deploy rules (hard-won, keep)

- Build command: `python3 scripts/build.py`. Build machine: **Standard,
  never Turbo**.
- `vercel.json` functions map lists explicit paths only, each
  `{"maxDuration": 10}`; **never pin `runtime`** for Node functions.
- Static data lives in top-level `data/v1/`, never under `api/` (Vercel
  does not serve static files from `api/`).
- No npm dependencies; `installCommand` is a no-op echo.
- Free-tier audit: one function, no cron, no database, no storage. The
  play engines load from the EmulatorJS CDN on the visitor's machine;
  nothing about play costs the project anything.

## 3. Snapshot procedure

1. In the working repo: `python3 scripts/build.py && node scripts/test_converter12.js && node scripts/test_portplay.js` — all green.
2. Copy the tree (minus `scripts/`, `tests/`, dev docs) into the
   `button-mash-live` checkout, commit under the astercast identity, push
   with `gh-push.py`, verify remote tree == snapshot tree.
3. Verify the live URL serves the new version and `/api/health` answers
   `status: "ok"`, service `portplay`.
