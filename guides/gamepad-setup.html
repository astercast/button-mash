Controllers in the browser

The gamepad setup guide: which controllers work, how to connect and test them, per-system remapping in this site's Player, and the honest troubleshooting list.

  • Needs: any USB/Bluetooth pad
  • ⏱ ~20 min
  • Beginner

01Why a controller changes browser games

Some games were designed around a pad, and it shows. Platformers, racers, twin-stick shooters, and fighting games all play better with analog sticks and real buttons than with arrow keys — and anything you play in this site's Player (the EmulatorJS console) was literally built for a controller. The good news: modern browsers speak gamepad natively. No drivers, no mapping software, no downloads — plug in and play.

02How browser gamepads work (the 60-second version)

Browsers expose controllers through the Gamepad API: a page asks for the list of connected pads with navigator.getGamepads(), and the browser fires gamepadconnected / gamepaddisconnected events when pads come and go. Each pad reports buttons as pressed-or-not values and sticks as axes between -1 and 1. Most controllers follow the "standard" mapping, which means button 0 is the bottom face button (A on Xbox, Cross on PlayStation) no matter which brand you plugged in.

The details live in two places: the W3C Gamepad specification and MDN's Gamepad API docs. You don't need to read either to play — but if you're building a web game yourself, that's the starting line.

03Pick your controller

  • Xbox (One / Series) — the safe default. Wired over USB or Bluetooth; the standard mapping just works everywhere.
  • PlayStation (DualShock 4 / DualSense) — excellent pads, wired or Bluetooth; some browsers show PlayStation labels, some show Xbox-style numbers. The positions are identical.
  • Switch Pro Controller — works over Bluetooth and USB; check the button mapping in a tester first, since its face layout is swapped vs. Xbox.
  • 8BitDo and other Bluetooth pads — usually fine; X-input mode (the Xbox-compatible mode) is the one browsers understand best.
  • Cheap no-name USB pads — often fine for 2D games; test every button before a tournament.

04Connect it: USB vs. Bluetooth

USB is the zero-fuss path: plug the cable in and the browser sees the pad within a second. For Bluetooth, put the controller in pairing mode (Xbox: hold the pair button; DualSense: hold PS + Create; 8BitDo: hold the mode-specific combo from its manual), then pair it in your OS Bluetooth settings like any device.

One honest caveat: some Bluetooth stacks add a few milliseconds of input lag — imperceptible in RPGs and platformers, worth knowing about for rhythm games and fighters. If a pad refuses to appear, try the cable before anything else.

05Test it before you play

Open html5gamepad.com with the controller connected and press buttons: you should see each input light up with its standard-mapping number. This one page answers every "is it the game or the pad?" question in ten seconds.

If the tester sees the pad but a game doesn't, the game probably needs a button press to "wake" the listing — click into the game and press any button. If the tester doesn't see it either, it's a connection problem, not a game problem.

06Gamepads in this site's Player

The Player (this site's EmulatorJS console) has gamepad support built in — Player 1's pad just works, no setup. For finer control, the per-system remapper (Player 2.1) lets you capture gamepad buttons per system: open the remap panel, pick a button, and press the pad button you want. Your mapping is stored per system in the browser and applied at boot.

Two honest notes: the remap overrides any mapping you set inside the engine's own menu, and Esc cancels a capture. If your pad has a non-standard layout, capture each button once and you're done forever.

07Which catalog games love a pad

Reach for the controller for: the arcade shelf (Robotron: 2084 is the twin-stick original; Defender and Joust were built for arcade sticks), the Flash-back machine (Fancy Pants Adventure, Alien Hominid), racers and runners (HexGL supports gamepad natively — check its controls line), and anything in the Player.

Stick to keyboard and mouse for: idle games, puzzle games, text adventures like Zork, and the strategy shelf — a pad adds nothing there. When in doubt, the game's controls line tells you what's intended.

08Troubleshooting: the honest list

  • Pad not detected: press any button after the page loads (browsers only list pads after first input), then check html5gamepad.com. Still nothing? Try USB.
  • Wrong button does the thing: the game assumed the standard mapping and your pad is exotic. Remap it in the Player's per-system remapper, or check the tester's mapping.
  • Two pads, wrong one is Player 1: browsers order pads by connection order — unplug and reconnect in the order you want them.
  • Steam is running: Steam's controller layer can swallow inputs before the browser sees them. Quit Steam or disable its controller support for desktop.
  • It works everywhere except one game: that game polls getGamepads() once at load instead of every frame. Reload the page with the pad already connected and press a button on the title screen.
