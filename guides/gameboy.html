1. The core: Gambatte, cycle-accurate

The Player's gb core is Gambatte — the default Game Boy backend in the official EmulatorJS core list (the alternate is mGBA). Gambatte emulates the hardware cycle-by-cycle, which is why its compatibility is essentially perfect, and since the Game Boy is 1989 hardware, that accuracy costs nothing on modern machines.

The Player detects .gb and .gbc files and boots Gambatte automatically. One core covers both the original Game Boy and the Game Boy Color.

2. BIOS notes (the short version: none)

The Game Boy's boot ROM (the falling-logo animation) is copyrighted firmware, but you don't need it: Gambatte boots games directly with a reimplemented boot process. No dumping, no attaching — though if you ever hear the phrase "boot ROM," this is what people mean.

3. Settings that matter

Open the engine's in-game menu (the ⚙ icon) while a Game Boy game is running:

  • Colorization palettes: original Game Boy games were monochrome — the core can colorize them with custom palettes (including the classic Super Game Boy look). The single most fun setting on this system.
  • Fast-forward: perfect for this library's slow intros and random battles.
  • Keep in Browser: under Settings → Save States, switch the engine to Keep in Browser so the Player 2.0 Save tool can export/import your states as files.

4. Performance: the easiest win in emulation

Game Boy emulation is the cheapest compute in the Player — full speed on any device that loads the page, including the weakest phone in the drawer. It's the system the picker quiz recommends for old devices, and it's right.

5. Saves & cheats in the Player

  • Save states — instant snapshots from the in-game menu; export/import/delete them with the Player 2.0 Save tool on player.html when Keep in Browser is on.
  • In-game saves — SRAM battery saves persist automatically.
  • Cheats — the Player 2.0 Cheats tool takes Game Genie and GameShark codes, stored per game and injected before boot; toggle in the engine's cheat manager.
  • Keyboard remap — the Player 2.0 Controls tool remaps Player 1's keyboard and gamepad bindings (applies on next boot).
